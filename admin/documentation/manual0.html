Complete Configuration Guide

This manual covers every function, every configurable setting, and every component of the DORNORI website. Whether you're setting up the shop, customizing themes, or building new pages—you'll find detailed explanations, code examples, and best practices here.

Version: 2.0
Updated: 2026
Tech: Vanilla JS, No Frameworks
ℹ️

For non-developers: Most features can be controlled by editing js/config.js — no coding required. Look for sections marked Configuration.

Foundations

How DORNORI Works

The DORNORI website is a Single Page Application (SPA) built with vanilla JavaScript. It loads once, then dynamically switches pages without full reloads. This makes navigation fast and smooth.

Startup Flow

index.html (loads CSS + font)
  ↓
site-boot.js (loads config, initializes modules)
  ↓
site-main.js (sets up language, theme, navigation)
  ↓
page-loader.js (renders the first page based on URL)

Core Principles

  • Configuration-Driven: Most features controlled via js/config.js, not hardcoded
  • No Dependencies: Pure JavaScript—no React, Vue, jQuery, or external libraries
  • Modular: Each feature (shop, slideshow, forms) is independent and can be disabled
  • Internationalized: All text lives in JSON language files, not HTML
  • Theme-Ready: Colors and styling via CSS variables—switch themes instantly
  • Lazy-Loading: Shop, forms, and embeds only load when needed

Core Configuration

The Config File

The file js/config.js is the brain of the website. It controls:

  • Site appearance (domain, paths, branding)
  • Supported languages and currencies
  • Navigation menu structure
  • Shop settings (tax, shipping, payment)
  • Feature flags (enable/disable features)
  • API endpoints and external services
⚠️

Always use valid JSON syntax in config.js. Trailing commas, missing quotes, or unmatched braces will break the entire site. When in doubt, check the browser console (F12).

Appearance Settings

Control the site's domain, base path, and root URL:

appearance: {
  base_path:  '/',                          // '/' or '/subdirectory/'
  root_url:   'https://yourdomain.com',  // used for canonical tags, emails
}
SettingPurposeExample
base_pathIf the site is in a subdirectory, set this. Otherwise '/''/shop/'
root_urlFull domain for canonical links and emails'https://dornori.com'

Paths Configuration

These paths are auto-resolved with base_path. Only change them if you reorganize the file structure:

paths: {
  countries_file:  'data/countries.json',
  profiles_file:   'data/profiles.json',
  shipping_file:   'data/shipping.json',
  lang_dir:        'lang/',
  content_dir:     'content/',
  icons_dir:       'assets/icons/',
  shop_dir:        'shop/',
  js_dir:          'js/',

Feature Flags

Enable or disable features globally:

features: {
  showLanguageSwitcher: true,     // language dropdown in top bar

How URLs Are Generated

The site automatically builds URLs based on the nav structure:

  • Parent item: /en/gallery/
  • Child item (internal): /en/gallery-grid/
  • Child item (external URL): Opens in new tab with noopener noreferrer

Site Structure

Pages & Content System

DORNORI is a Single Page Application (SPA). When you click a nav item, the site fetches the HTML for that page and displays it without a full reload. This makes navigation smooth and fast.

How Pages Work

  1. User clicks a nav item (e.g., "Gallery")
  2. Site fetches content/en/gallery.html (or other language)
  3. HTML is injected into the page
  4. Any components (slideshows, forms, shop) are mounted
  5. URL updates without a full page refresh

Register a Page

In js/config.js, add it to the pages object:

pages: {
  gallery: { file: 'gallery.html' },
  about: { file: 'about-us.html' },
  contact: { file: 'contact.html' },
  // ... all other pages
}

Create Page Files

For each page and each language:

content/en/gallery.html
content/nl/gallery.html
content/de/gallery.html
(repeat for all 8 languages)

Page HTML Structure

Keep page HTML simple and semantic:

<div class="container">
  <h1>Page Title</h1>
  
  <section>
    <h2>Section Heading</h2>
    <p>Paragraph text.</p>
  </section>
  
  <<!-- Slideshow -->
  <div gallery-images="img1, img2" gallery-folder="images/"></div>
  
  <<!-- Form -->
  <form data-form="contact">
    <input type="email" name="email" required>
    <button type="submit">Send</button>
  </form>
</div>

Best Practices

  • Use semantic HTML: <h1>, <h2>, <section>, <article>, <p>
  • One <h1> per page — this is your main page title
  • Use CSS utility classes: .container, .hero, .section, .grid-2cols
  • Link internally using format: /en/page-slug/
  • Optimize images: Provide .webp + .jpg via <picture> tag
  • Test on mobile — the CSS is mobile-first
💡

Copy as template: When creating a new page, copy an existing one in the same language and edit the content. This ensures all HTML structure and CSS classes are correct.

Multi-Language

Internationalization (i18n)

DORNORI supports 8 languages out of the box: English, Dutch, German, French, Spanish, Italian, Portuguese, and Czech. All user-facing text lives in JSON language files, not in HTML.

Structure

lang/
├── en/common.json       // English UI strings
├── en/products.json     // English product names
├── en/form.json         // English form labels
├── nl/common.json       // Dutch
├── de/common.json       // German
// ... etc for all 8 languages

common.json Structure

This file contains all UI strings (nav labels, buttons, messages, etc.):

{
  "nav": {
    "gallery": { "label": "Gallery", "mobileLabel": "Gallery" }
  },
  "footer": {
    "columns": [
      { "heading": "Company", "links": { "about": "About Us" } }
    ]
  },
  "url_slugs": {
    "gallery": "gallery",
    "about": "about"
  }
}

Translate Text in JavaScript

Use the Shop.t(key, fallback) function:

Shop.t("add_to_cart", "Add to Cart")  // returns translated text

Add a New Translation

  1. Edit lang/en/common.json and add your key-value pair
  2. Repeat for all 7 other language files (nl, de, fr, es, it, pt, cs)
  3. Use in your code with Shop.t("your_key")
⚠️

Important: Always update all 8 language files. If a key is missing from a language file, it falls back to the English version or the provided fallback text.

Language Switching

The site detects language from:

  1. URL path (e.g., /de/gallery/ → German)
  2. URL query (e.g., ?lang=nl)
  3. Saved preference (localStorage)
  4. Browser language
  5. Fallback to default (English)
Design System

Themes & Profiles

DORNORI comes with multiple color themes (profiles) that users can switch between. All themes are defined via CSS variables, so switching is instant with no page reload.

Available Themes

Open data/profiles.json to see all themes. Each has:

  • A name (e.g., "Dark", "Light")
  • CSS color variables (background, text, accents)
  • Applied via css/profiles.css

Customize a Theme

Edit data/profiles.json to change colors:

{
  "name": "Dark",
  "colors": {
    "background": "#1a1714",
    "text": "#faf8f5",
    "accent": "#c8a96e",
    "border": "#333333"
  }
}

Add a New Theme

  1. Edit data/profiles.json and add a new profile object
  2. Define all color variables
  3. Add corresponding CSS in css/profiles.css under a new selector
  4. The new theme appears in the settings menu automatically
ℹ️

How it works: Each theme has a CSS class (e.g., .theme-dark) applied to the root element. All CSS variables are scoped to that class. Changing the theme just swaps the class.

Slideshow Gallery

DORNORI includes a powerful slideshow component for displaying image galleries. No configuration needed—just add one HTML element to any page.

Basic Usage

Add this to your page HTML:

<div
  gallery-images="image1, image2, image3"
  gallery-folder="images/gallery/">
</div>

All Attributes

AttributeValuesDefaultDescription

gallery-size"800x600" or "16/9""16/9"Dimensions. Use aspect ratio or pixel size
gallery-border"yes" | "no""no"Show border around gallery
gallery-shape"rounded" | "square""square"Corner style
gallery-intervalmilliseconds4000Auto-advance delay (auto mode only)

Examples

Simple Gallery

<div gallery-images="sunset, mountain, forest" 
     gallery-folder="images/photos/"></div>

Auto-Advancing Hero Slideshow

<div gallery-images="hero1, hero2, hero3"
     gallery-folder="images/hero/"
     gallery-size="16/9"
     gallery-mode="auto"
     gallery-interval=5000
     gallery-fullbleed="yes"></div>

Rounded Gallery with Border

<div gallery-images="item1, item2, item3, item4"
     gallery-folder="images/products/"
     gallery-shape="rounded"
     gallery-border="yes"></div>

Interactions

  • Desktop: Click left half to go back, right half to go forward
  • Mobile: Swipe left/right
  • Both: Click dot indicators to jump to a slide
  • Auto mode: Automatically advances; timer resets on any user interaction

Image Format

The slideshow automatically loads WebP first (fast, modern), then falls back to JPEG:

images/gallery/sunset.webp   // primary (modern browsers)
images/gallery/sunset.jpg    // fallback (older browsers)
💡

Pro tip: For better performance, optimize images to web resolution (e.g., 1200px wide) and convert to WebP. Use tools like ImageMagick or Squoosh.

DORNORI includes a versatile form system for contact forms, newsletters, and custom fields. Forms validate, handle Turnstile CAPTCHA, and post to a backend API.

Form Embed

Add a form anywhere on your page:

<form data-form="contact">

  <input type="email" name="email" placeholder="Your Email" required>
  <textarea name="message" placeholder="Message" required></textarea>

Translate form labels in lang/[code]/form.json:

{
  "contact": {
    "name": "Your Name",
    "email": "Email Address",
    "message": "Your Message",

endpoints: {

Turnstile CAPTCHA

Enable bot protection:

turnstile: {
  sitekey: '0x4AAAAAACxsga5y-bJ_qkzC',  // get from Cloudflare

⚠️

Important: Turnstile is shown only on form submit. You need a Cloudflare Turnstile account and the correct sitekey. Without it, forms will show a placeholder message.

E-Commerce

Shop System

DORNORI includes a fully-featured e-commerce system with product catalog, shopping cart, checkout, and payment processing. The shop is powered by JavaScript and can be embedded on any page.

Shop Features

🛍️ Product Catalog

Browse products with images, descriptions, prices, and stock levels.

🛒 Shopping Cart

Add/remove items, adjust quantities, see real-time totals.

💳 Payment

PayPal or Stripe checkout with full order details.

🌍 Multi-Currency

Display prices in EUR, USD, GBP, and more with live conversion.

📦 Shipping

Automatic calculation based on weight and location.

🌐 Multi-Language

Product names, descriptions, and UI in 8 languages.

How the Shop Works

  1. Load products: Shop fetches data/products.json
  2. Apply translations: Product names/descriptions from lang/[code]/products.json
  3. Render UI: Browse page, product detail, cart, checkout
  4. Manage cart: Saved to localStorage, survives page refresh
  5. Process payment: PayPal or Stripe (configurable)
E-Commerce

Shop Configuration

Payment Processor

Choose between PayPal or Stripe:

payment: {
  activeProcessor: "paypal",  // or "stripe"
  paypal: {
    clientId: "YOUR_PAYPAL_CLIENT_ID",
    currency: "EUR",
    intent: "capture",
  },
  stripe: {
    publishableKey: "pk_live_...",
    currency: "eur",
    intentEndpoint: "https://api.example.com/stripe-intent",
  }
}

PayPal Setup

  1. Go to PayPal Developer Dashboard
  2. Create an app in Sandbox (testing) or Live (production)
  3. Copy your Client ID
  4. Paste into CONFIG.payment.paypal.clientId

Stripe Setup

  1. Go to Stripe Dashboard
  2. Find your Publishable Key in API Keys section
  3. Paste into CONFIG.payment.stripe.publishableKey
  4. Set up a backend endpoint for creating payment intents

taxRate: 0.21,              // 21% VAT

Cart Events

The shop emits custom DOM events when the cart changes:

document.addEventListener("shop:cartUpdated", (e) => {

  const itemCount = cart.reduce((a, i) => a + i.qty, 0);

});

// In JavaScript

// Success

E-Commerce

Currency & Shipping

Currency Support

Currency data is pulled from data/countries.json. Each country has:

{
  "code": "US",
  "name": "United States",
  "currency": "USD",
  "currency_symbol": "$",
  "currency_rate_to_eur": 0.92,
  "currency_decimals": 2,
  "currency_locale": "en-US"
}

Currency Functions

// Get list of available currencies
Currency.list()  // → [{code: 'EUR', ...}, {code: 'USD', ...}, ...]

// Get active currency
Currency.getActive()  // → 'USD'

// Convert EUR to active currency
const inUSD = Currency.convert(100)  // → 92

// Format price for display
Currency.fmt(100)  // → "$92.00" (or "€100.00", etc.)

// Switch currency
Currency.setActive("GBP")  // emit currency:changed event

Shipping Calculation

Shipping is based on:

  • Order total: Free if over threshold, otherwise add base + weight cost
  • Weight: Heavier items add cost per kg
  • Destination: Can vary per country (configured in data/shipping.json)

Shipping API

// Get shipping cost for cart
const cartItems = [
  { productId: "lamp-001", qty: 2 }
];
const country = "US";
const shipping = calculateShipping(cartItems, country);
console.log(shipping);  // → { cost: 12.50, label: "Standard 3-5 days" }
JavaScript API

Shop API — Overview

The Shop object is the main API for interacting with the e-commerce system. All functions are available globally after the webshop:ready event fires.

Wait for Shop to Load

// Always use this pattern to ensure Shop is ready

  // Now safe to call Shop.* functions
  const products = await Shop.loadProducts();
  console.log(products);
});

JavaScript API

Events

The shop dispatches custom DOM events that you can listen to:

EventWhen it firesDetail
webshop:readyShop modules loaded and initialized—
shop:cartUpdatedItem added/removed, qty changed, cart cleared{ cart: [...] }
shop:langChangedLanguage switched{ lang: "nl" }
currency:changedCurrency switched—
payment:successOrder completed successfully{ orderRef, processor, details }
payment:cancelUser cancels payment{ orderRef, processor }
payment:errorPayment failed{ orderRef, processor, error }

Example: React to Cart Changes

document.addEventListener("shop:cartUpdated", (e) => {
  const cart = e.detail.cart;
  const itemCount = cart.reduce((a, i) => a + i.qty, 0);
  
  // Update UI with new count
  document.getElementById("cart-count").textContent = itemCount;
});

Example: Language Change

document.addEventListener("shop:langChanged", (e) => {
  console.log("Language switched to", e.detail.lang);
  // Re-render any custom UI that uses Shop.t()
});

Troubleshooting

Page Doesn't Load

Problem: Page shows blank or 404 error

Solution:

  1. Check F12 Console for errors
  2. Verify the page exists: content/[lang]/[slug].html
  3. Ensure config.js has the page registered: pages: { 'slug': { file: 'slug.html' } }
  4. Check that base_path matches your server setup

Navigation Items Don't Appear

Problem: Nav menu is empty or missing items

Solution:

  1. Edit config.js and check the navigation array
  2. Verify enabled: true on nav items
  3. Check language files have translations: lang/en/common.json → "nav" object
  4. Ensure icon files exist: assets/icons/[icon-name].svg

Shop Doesn't Load

Problem: Shop page blank or products not showing

Solution:

  1. Check F12 Network tab — is data/products.json loading?
  2. Verify data/products.json has valid JSON syntax
  3. Ensure product images exist: images/products/[product-id].webp
  4. Check that webshop:ready event fires (F12 Console)

Payment Button Missing

Problem: PayPal/Stripe button not showing on checkout

Solution:

  1. Verify payment processor is set: CONFIG.payment.activeProcessor = "paypal"
  2. For PayPal: Check CONFIG.payment.paypal.clientId is set (not empty)
  3. For Stripe: Check CONFIG.payment.stripe.publishableKey starts with pk_
  4. Check F12 Console for API load errors

Language Switcher Broken

Problem: Language doesn't change or UI text stays in English

Solution:

  1. Check features.showLanguageSwitcher = true
  2. Verify all language files exist: lang/[code]/common.json for all 8 languages
  3. Ensure JSON syntax is valid (no trailing commas, unmatched braces)
  4. Clear localStorage and refresh: localStorage.clear()

Slideshow Not Working

Problem: Slideshow doesn't appear or images don't load

Solution:

  1. Verify HTML has gallery-images attribute with image names
  2. Check gallery-folder path is correct (no leading/trailing spaces)
  3. Ensure images exist: [folder]/[name].webp and [folder]/[name].jpg
  4. Check F12 Network tab for 404 errors on images

Console Errors

Open F12 → Console tab and look for error messages:

  • "Cannot read property 'x' of undefined" — Check config.js for missing values
  • "Failed to load config" — Check paths in config.js (base_path)
  • "JSON parse error" — Check language/product JSON files for syntax errors
  • "404 on products.json" — Check file exists and path is correct
💡

Pro tip: Always check the F12 Console first. Most issues are obvious JSON syntax errors or missing files. The console shows exactly what's wrong.
